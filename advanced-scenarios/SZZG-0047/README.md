## Purpose

A feature branch makes `PortParser.parse` swallow `NumberFormatException` and
return `FALLBACK_PORT` (0), then adds a privileged-port check on top. The branch
is squash-merged into `main` as a **single-parent** commit whose subject is the
GitHub squash message of the pull request. The squash commit `c3` is the direct
BIC on `main`; the feature commit `c1` that first wrote the swallowing catch block
is the origin, reachable through the `feature` branch but not an ancestor of the
fix. A tool that mines `main` sees one commit that both introduced the fault and
added an unrelated method.

Rewritten 2026-09-21 (issue #13) from the shared `Range.contains` template; the
history shape, oracle and coverage dimensions (`bic_depth` 1, three distractors
on the fault file, 5 commits, 2 refs) are unchanged.

`squashes` and stay reachable through `feature`.

## What a tool must do

Report `c3` under the default oracle; `c1` is context. A tool that follows the
`feature` branch will find `c1` first — the origin-aware variant tolerates it
with half credit, the default does not, because `c1` is not an ancestor of the
fix and a `main`-line bisect never sees it.
