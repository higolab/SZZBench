# SZZG-0129: Octopus merge with the faulty branch on a non-first parent

## Purpose

Every other merge in the suite has two parents. Here three feature branches,
each touching its own file, are integrated with one octopus merge, and the
fault is on the second of them. Along `main`'s first-parent history the change
appears with the merge commit; the commit that made it is only reachable
through the merge's third parent.

## Commit structure (generated)

```text
* b85ba10  Allow a request that uses the quota exactly                  <- BFC (c2)
*---.   b3eee7c  Merge branches 'audit', 'quota' and 'format' into main   (m1, four parents)
|\ \ \
| | | * 833983a  Pad report keys to a fixed width                        (f1, branch format)
| | * 3cf50ac  Keep the time of each audit entry                         (a1, branch audit)   [ordering per git log --graph]
| * b945594  Refuse a request that would fill the quota completely       <- BIC (q1, branch quota)
|/
* 5af7fe0  Add the quota policy, the audit log and the report formatter  (c0)
```

`git rev-list --parents -n 1 b3eee7c` lists `5af7fe0 3cf50ac b945594 833983a`:
`c0`, then `a1`, `q1`, `f1` in the declared order. The merge is generated by a
single `git merge --no-ff --no-commit <a1> <q1> <f1>`; the three branches touch
three different files, so it is clean — the only kind git's octopus strategy
can produce.

## Expected BIC / BFC

- BIC: `q1` (`exact_set`, `required: [q1]`)
- `related_but_not_correct`: `m1` — the merge that carried the change onto `main`
- BFC: `c2`

## Measured blame outcome at BFC^

Blaming the line `c2` deletes returns `q1` (`b945594`): `git blame` follows all
parents. `git log --first-parent main` shows `c2, m1, c0` — the merge is the
first-parent commit that changed `QuotaPolicy.java`.

## What a tool must do

Report `q1`. A tool that follows only the first parent, or only the last
listed parent, attributes the change to `m1`.

## Factors

- `merge`
- `octopus-merge`
- `bic-on-non-first-parent`
- `multi-branch-integration`
