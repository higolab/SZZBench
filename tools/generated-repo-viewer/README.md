# SZZBench Generated Repository Viewer

This tool is a local Web viewer for repositories generated by SZZBench.

Unlike the `scenario.yml` state viewer, this viewer reads the **actual generated Git repository** under `generated-input-repos/` and uses Git commands through a local Node.js backend.

## What it shows

- Generated repository list
- Scenario metadata
- Logical commit ID to actual Git hash mapping
- Commit timeline
- Files at each selected commit
- File content at the selected commit
- Diff from the selected commit's parent
- `git blame` output for a selected file
- Bug oracle from `metadata/scenario.yml`
- `verify-result.json`, if available

## Requirements

- Node.js
- npm
- Git available on `PATH`

## Usage

From the SZZBench repository root:

```bash
cd tools/generated-repo-viewer
npm install
npm run dev
```

Open:

```text
http://127.0.0.1:5174
```

The backend API runs on:

```text
http://127.0.0.1:4174
```

## Expected generated repository layout

The viewer expects generated repositories like this:

```text
generated-input-repos/
  SZZ-0006/
    default/
      repo/
        .git/
        ...
      metadata/
        scenario.yml
        commit-map.json
        verify-result.json
```

## What the API accepts

The backend runs Git on request values, so it checks them first (issue #132):

- `target` must be a generated output under the project root. The check follows symbolic links, so a link that points out of the project is refused.
- `commit` must be a commit hash (7 to 64 hexadecimal digits), as `/api/repository` lists them. A value such as `HEAD`, a branch name or anything starting with `-` is refused. `git show` and `git ls-tree` also get the revision after `--end-of-options`; `git blame` gets the hash and then the file after `--`, the one form that works on every supported Git (2.39 does not honour `--end-of-options` there).
- `file` must be a path inside the commit's tree, as `/api/tree` lists it: relative, `/`-separated, with no `..` or empty component.
- Only same-origin requests are served. The pages are same-origin in both modes (`npm run dev` proxies `/api` through Vite, `npm start` serves `dist/` from the backend), so the API sends no CORS header, and it refuses a request that the browser marks as coming from another site (`Sec-Fetch-Site`). Tools such as `curl` send no such header and are not affected.
- An error that Git or the file system reports is logged by the server and answered with a generic message, so that responses do not reveal the machine's paths.

Two environment variables change where the backend looks: `SZZBENCH_REPO_VIEWER_PORT` (default `4174`) and `SZZBENCH_REPO_ROOT`, the SZZBench checkout whose `generated-input-repos/` it reads (default: the checkout the viewer is in). `tests/test_repo_viewer.py` uses both.

## Notes

This viewer does not modify repositories. It only reads generated repositories and metadata.
